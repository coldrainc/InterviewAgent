# 面试 Agent Harness 一体化系统 - 产品需求文档

## Overview

- **Summary**：把现有「模拟面试 + 刷题 + 复习站」三个松散功能，重构为一套以**学习闭环**为核心的 Agent harness 系统：用户以面试官 / 面试者 / 刷题者三种身份进入同一工作台，系统完成「面试 → 评估报告 → 薄弱项 → 个性化计划 → 每日任务 → 打卡 → 数据回流 → 再面试」的完整闭环；配套真实日历打卡、连续学习 streak、学习驾驶舱和系统提醒，UI 统一为一套简洁的浅色/深色双主题设计语言。
- **Purpose**：现状三大模块各自为战——面试只有自由文本评语、不落分；刷题无作答、答错不进错题本；复习计划是与用户无关的静态模板、「今日」靠进度比例推算、学习时长永远为 0；三套分类法并存、两套刷题入口、Ops 研发功能混入主导航。用户需要的是一个**每天打开就知道该做什么、做完有反馈、长期看得见成长**的备考工作台，而不是六个功能页。
- **Target Users**：
  - 主力用户：准备技术面试（AI 工程方向为主，兼顾公考/行业题库）的求职者，桌面端重度使用；
  - 双角色用户：既需要「Agent 当面试官拷问我」（interviewer 模式），也需要「我当面试官、Agent 当候选人陪练提问」（candidate 模式）；
  - 自助备考用户：依赖计划生成、每日打卡、错题本、自我介绍/STAR/A4 素材完成系统复习。

## Goals

1. **一个闭环**：面试评估、刷题错题、复习任务三类数据互相打通——面试报告的薄弱维度自动影响计划任务排布与刷题推荐；错题掌握度反哺计划；计划中的模拟任务可一键拉起面试会话。
2. **三个模式**：面试官模式 / 候选人模式 / 刷题模式在同一 harness 内清晰切换，模式切换不离开上下文。
3. **计划个性化**：复习计划由 LLM 结合简历、目标岗位/JD、历史面试评分、错题分布生成，任务可溯源到生成理由。
4. **打卡真实化**：计划绑定开始日期，「今日任务」按真实日历；支持每日打卡、学习时长记录、连续学习 streak、成就徽章、每日提醒。
5. **面试有结论**：每场可评分面试结束后产出结构化报告（总分 + 7 维度分 + 证据 + 优势/风险标签 + 行动建议），历史可查、趋势可见。
6. **刷题有闭环**：题目可作作答、即时判分/讲评、答错自动入错题本、掌握度随作答更新、统计真实。
7. **交互简洁**：信息架构收敛为「今日 / 面试 / 训练 / 复习 / 我的」五区；Ops 等研发功能移出主导航；全应用一套 v3 设计语言 + 双主题。

## Non-Goals

- 不做移动端（Android/iOS/小程序）新功能：后端 API 保持多租户通用、为多端预留，但本期只交付 Electron 桌面端 UI。
- 不做真人对练、音视频通话、语音识别（自我介绍跟读录音不在本期；现有假麦克风按钮移除或隐藏）。
- 不做在线协同/社交/排行榜。
- 不重构计费体系（复用现有积分）；LLM 个性化生成与报告评分按现有模型计费扣费。
- 不做服务端消息推送（微信服务通知等）；每日提醒走 Electron 本地系统通知。
- 不迁移多副本部署架构（会话内存态问题仅记录，不在本期解决）。

## Background & Context

**已具备的底座（复用，不重造）**：

- 后端 FastAPI + PostgreSQL 23 张表，多租户隔离 + RBAC + 积分计费 + 支付闭环；SSE 流式；LangGraph/显式双引擎 Agent loop；护栏（注入扫描/脱敏/截断）；简历解析与对象存储；后台 job + 事件流 + trace 可观测；RAG 知识库框架。
- 面试会话持久化（sessions/turns/memory_items），支持 rewind、transcript、双模式。
- 复习站四级结构（plans/phases/days/tasks）+ progress（done/note/mastery/elapsed）+ intro_scripts/star_cards/a4_memory；题库 v2（practice_questions + wrong_book 表，attempt_count/correct_count 字段已备）。
- 前端：8 screen 单状态机路由、v3 设计体系（CSS 变量、卡片/chip/抽屉/toast/庆祝/快捷键）、双主题 token、侧栏折叠、复习站 6 Tab、计划向导 4 步表单 + Gantt 预览。

**关键缺口（本期要补）**：

- 面试：rubric 7 维度只存在于 prompt，不落分；候选人模式无评估无终点；报告页不存在；面试与题库/计划零联动。
- 刷题：/practice/attempt 判分不入库；选项不可点选；错题本有接口有表但 UI 不渲染、答错不自动收录；两套题库表/两套 UI/三套 taxonomy。
- 计划：生成是静态规则模板；天无日期；无打卡表/streak/提醒/统计接口；素材与计划内容无写接口；默认内容硬编码开发者本机绝对路径。
- 数据：无学习 dashboard 聚合 API；跨域薄弱项画像不存在。
- IA：8 screen 平铺；刷题两处入口；设置三处入口；Ops 混入用户导航；Topbar 在复习站显示错误 chip；假数据（本周新增、已用时、随机 10 题）。

## 用户旅程

1. **晨间打开** → 今日页：打卡 streak 火焰、今日 3 个任务（含 1 个模拟面试任务）、昨日学习时长、一句 AI 建议 → 点「开始今日模拟面试」。
2. **模拟面试**（面试官模式）→ 8 轮问答，界面显示第几题/考察方向/计时 → 结束自动生成报告：7 维评分雷达、3 条证据、2 个薄弱维度 → 「把薄弱项加入复习计划」。
3. **刷题**：报告推荐「RAG 优化」题组 → 作答选择/主观题 → 即时判分 + LLM 讲评 → 答错自动进错题本，掌握度 1 星。
4. **复习打卡**：今日任务勾选完成、录入 45 分钟时长、薄弱任务标星 → 连续第 6 天打卡弹成就 → 数据回流首页。
5. **候选人陪练**：切换模式练提问，Agent 以候选人口吻作答，结束给出「提问质量」反馈（追问深度/方向覆盖）。
6. **素材日**：自我介绍倒计时练习、STAR 卡翻面、A4 打印；练习次数真实记录。

## Functional Requirements

### FR-1 信息架构与导航重构

- 侧栏收敛为五区：**今日（驾驶舱）/ 面试（模拟面试 + 面试报告）/ 训练（统一刷题 + 错题本）/ 复习（复习站 + 计划生成）/ 我的（配置、账户、设置、运维）**。
- 运维（Ops/jobs/eval）入口收进「我的 → 管理员/运维」，不再与学习功能平级。
- 两套刷题合并为单一「训练」页，使用统一题库分类法（与行业 taxonomy 对齐，废弃硬编码 7 类/5 类两套）。
- 页面间闭环跳转带上下文：报告 → 推荐题组/计划任务；计划任务（simulation）→ 一键拉起对应模式面试；错题 → 对应知识点任务。
- Topbar 在所有页面标题与 chip 正确（复习/训练页不显示会话 chip）。
- 历史会话列表支持查看全部（不再只 6 条）、按模式筛选、展示报告分数摘要。

### FR-2 今日学习驾驶舱（新增首页）

- 顶部：连续打卡天数（streak）+ 今日学习目标 + 打卡按钮。
- 今日任务卡：按真实日历从进行中计划派生（任务列表 + 完成态 + 关键任务标记），可直接勾选/跳转。
- 快捷开始：模拟面试（面试官模式）/ 陪练（候选人模式）/ 随机刷题 / 继续昨日。
- 数据条：本周学习时长、面试场次与最近评分、刷题数与正确率、计划完成率（均来自真实聚合接口）。
- AI 今日建议：基于最近一次面试报告薄弱项 + 错题分布生成一句话建议与推荐动作（可复用 LLM，失败时降级为规则文案）。

### FR-3 模拟面试 harness 增强

- 面试中可见：当前题号 / 总轮次、当前考察方向（focus area）、正计时；候选人模式显示「你已提问 N 个问题」。
- 双模式在会话内可从设置区切换默认角色（保留 Setup 页，入口收敛到「我的 → 面试配置」与面试页内快捷入口）。
- 面试官模式：达到轮次/方向耗尽正常收尾；候选人模式：达到可配置轮次后收尾并进入评估。
- 模拟面试任务可从复习计划任务卡一键发起（携带岗位/行业上下文），会话记录关联 plan_task_id。
- 面试记录可导出纯文本（已有 transcript，前端加入口）。

### FR-4 结构化面试评估与报告

- 面试官模式结束时，LLM 输出**结构化 JSON 评估**：总分（0-100）、7 维度分（沟通表达/技术深度/项目真实度/工程取舍/生产意识/岗位匹配/逻辑结构，各 0-5）、每题简评、3+ 条证据引用、优势标签、风险/薄弱标签、3 条可执行建议（每条关联知识点分类）。
- 候选人模式结束时，输出「提问质量」评估：追问深度、方向覆盖、问题区分度、改进建议。
- 报告落库（新表），面试报告列表页展示：日期、岗位、模式、总分、趋势（较上次 ±）；报告详情页展示维度条/雷达、证据、标签、建议。
- 报告页提供「薄弱项加入复习计划」：选择进行中计划，把建议转为计划任务（带 source=report 标记与溯源链接）。
- 历史趋势：最近 N 场总分与维度分折线/条形。

### FR-5 刷题训练与错题闭环

- 统一训练页：题目支持**真实作答**——选择题点选提交、主观题书写提交；即时判分（选择题规则判分；主观题 LLM 评分 + 讲评，复用现有 attempt 接口并升级）。
- 每次作答落库（新表 practice_attempts：题/用户/答案/对错/分数/用时/时间）。
- 答错**自动收录错题本**并维护 attempt_count/correct_count/last_attempt_at；错题本页可筛选（标记类型/掌握度/分类/关键词）、重做、移除。
- 掌握度随作答升降（答对 +、连对升级、答错回落）；「只看错题/未掌握」筛选真实生效。
- 训练统计真实：做题数、正确率、本周新增、分类掌握分布。
- 题库来源统一：v2 practice_questions 为主；v1 civil_service 数据迁移/别名兼容；上传题库走 v2 结构。

### FR-6 LLM 个性化复习计划生成

- 生成向导输入：目标岗位/职级/公司、天数、每日时长、重点方向、简历（可选）、**是否参考历史面试报告与错题分布**（默认是）。
- LLM 生成：阶段划分、每日主题与验收标准、任务（区分必做 critical / 模拟 simulation / 刷题）、每个任务给出生成理由；模拟任务关联模式与考察方向，刷题任务关联分类。
- 生成消耗积分（按模型 token 计费），失败降级为现有规则模板。
- 计划绑定**开始日期**（默认明天/今天可选），天派生 scheduled_date；支持归档/编辑（标题/天/任务/素材写接口补齐）。
- 进行中计划收到「薄弱项任务」追加时，插入到最近未完成日。
- 移除所有开发者本机绝对路径依赖（file:// 链接、INTERVIEW_CONTENT_ROOT 硬编码），资料链接改为内置知识库文档引用或可访问 URL。

### FR-7 日历化打卡与激励

- 打卡：每日完成任意任务即视为当日学习；提供显式「今日打卡」按钮；打卡记录落库（日期/完成任务数/时长/笔记）。
- 学习时长：任务卡与今日页可录入/累加 elapsed_minutes（计时器 + 手动补录），统计真实聚合。
- Streak：连续学习天数（按打卡日计算），断签提示；首页与复习站展示火焰 + 天数。
- 成就徽章：首场面谈、首场报告、首个 7 天 streak、刷题 100、错题清零、计划完成等里程碑，达成弹 toast + 徽章墙（我的页）。
- 每日提醒：Electron 本地系统通知（可开关、可设时间），内容含今日待办数；未设置计划时不提醒。

### FR-8 素材库（自我介绍 / STAR / A4）

- 三类素材支持**新建/编辑/删除**（后端写接口补齐，前端卡片内编辑）。
- 自我介绍练习：倒计时保留，练习次数/平均时长真实持久化（后端记录，不再只存 localStorage）；移除假录音按钮或替换为「专注练习」模式说明。
- STAR 卡翻面/抽屉保留；A4 打印/导出保留且打印样式在双主题下均白底。

### FR-9 学习数据中枢（后端聚合）

- 统一 dashboard 聚合接口：streak、今日任务与完成态、本周/累计时长、面试场次/最近分/均分、刷题数/正确率、计划完成率、薄弱知识点 Top3。
- 跨域画像：面试薄弱标签 + 错题分类分布 → 计划生成与首页建议的输入。
- 所有统计来自真实数据；前端删除假统计（min(12,…) 等）。

### FR-10 视觉与交互统一

- 全应用统一 v3 设计语言（卡片/chip/按钮/输入/抽屉/toast/骨架屏），旧页面（chat/setup/account/study/ops）迁移到同一套 token 与组件风格；双主题（浅色/深色）全页面有效。
- 简洁交互：每页主操作唯一且明显；危险操作二次确认；乐观更新 + 失败回滚 + 可感知错误提示（复习站静默吞错改为可见 toast）。
- 快捷键保留并补充：⌘B 侧栏、刷题 1/2/3 与方向键、打卡 D 键等，统一在设置页列出。

## Non-Functional Requirements

- **NFR-1 兼容与回归**：现有会话/简历/计费/支付链路不被破坏；复习站已有计划数据（14 天计划）在新日历模型下可平滑赋予开始日期。
- **NFR-2 数据隔离**：所有新表沿用 tenant_id + user_id 隔离；聚合接口只统计当前用户。
- **NFR-3 性能**：dashboard 聚合接口 P95 < 800ms（数据量按单用户千级任务/答题）；首屏渲染不新增明显阻塞；SSE 流式不回退为阻塞。
- **NFR-4 可靠性**：打卡/作答/报告写入幂等；前端乐观更新失败可回滚；LLM 结构化评估解析失败时降级为文本评估并保底可落库。
- **NFR-5 可维护性**：App.jsx god component 按页面拆分状态与数据加载（页面自治取数，参考 ReviewSitePage 模式）；styles.css 按区块注释组织，不再新增第二套设计语言。
- **NFR-6 双主题**：新增页面/组件必须使用语义 token，禁止硬编码颜色；深色下对比度达标（正文 ≥ 4.5:1）。
- **NFR-7 可测试**：后端新逻辑补 pytest（报告结构化解析、streak 计算、聚合统计、错题自动收录、LLM 计划降级）；前端构建 0 error。
- **NFR-8 计费**：LLM 计划生成与主观题讲评纳入积分扣费，余额不足给出明确引导。

## Constraints

- **Technical**：Electron + React 18 + Vite 前端（不引重型框架，路由可用轻量状态机或 react-router）；FastAPI + SQLAlchemy async + PostgreSQL + Alembic 迁移；LLM 经现有 model_runtime（OpenAI 兼容/Anthropic/DeepSeek）；桌面通知经 Electron main 进程 IPC。
- **Business**：复用现有积分体系，不新增付费点；Ops/管理员功能仅 admin 可见。
- **Dependencies**：LLM 结构化输出依赖模型 JSON 能力（需解析容错）；本地通知依赖 Electron Notification 权限。

## Assumptions

- 单用户桌面端使用为主，同一账号多端并发写打卡的概率低（streak 按服务端日期聚合，天然幂等）。
- 现有 14 天计划用户可接受系统默认开始日期 = 首次打开新版当日（可手动改）。
- 主观题 LLM 评分为辅助参考，不追求考试级判分精度。
- v1 公考题库数据量小，迁移到 v2 表一次性完成。

## Acceptance Criteria

### AC-1：五区导航闭环
- **Type**： `rule`
- **Given**：用户登录后进入应用
- **When**：查看侧栏并在各区间切换
- **Then**：侧栏只呈现 今日/面试/训练/复习/我的 五区；Ops 仅管理员在「我的」内可见；从面试报告可跳到推荐刷题与计划任务；从 simulation 任务可一键发起面试
- **Pass Condition**：五区结构、闭环跳转、Ops 收敛均在运行应用中可操作；无死入口
- **Evidence**：手动走查 + 代码路由表核对

### AC-2：今日驾驶舱真实数据
- **Type**： `rule`
- **Given**：用户有进行中计划与历史学习数据
- **When**：打开今日页
- **Then**：streak、今日任务、本周时长、面试/刷题统计全部来自后端聚合接口；断开后端时明确提示而非假数据
- **Pass Condition**：接口返回与数据库记录一致；前端无 min(12,…) 类假统计
- **Evidence**：API 返回与 DB 查询比对

### AC-3：面试报告结构化落库
- **Type**： `rule`
- **Given**：一场面试官模式面试完成
- **When**：评估阶段结束
- **Then**：生成含总分、7 维度分、证据、标签、建议的报告并落库；报告列表/详情/趋势可见；LLM JSON 解析失败时降级为文本报告且会话不丢
- **Pass Condition**：报告记录存在且字段完整；报告页可查；故障降级有日志与兜底
- **Evidence**：新表数据 + 报告页截图 + 降级测试

### AC-4：薄弱项回流计划
