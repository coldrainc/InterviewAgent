# 陈雨寒 | 面试自我介绍模板（四档，按场景直接背）

> 原则：**统一叙事骨架 + 按场景调详略**。每版都遵循：
> 「基本信息（3秒记住你）→ 定位 & 核心能力（让面试官知道你解决什么问题）→ 最近两段大厂经历 & 2-3 个量化成果 → 技术深度三选 → 主动引导提问」
>
> 核心能力统一锚定：**「跨端（鸿蒙 / KMP / RN）× AI 应用（Workflow Agent + RAG）× 全栈工程化」**。
> 不要泛泛说"我会很多"，要说「我是做 X 方向的，做过 A/B/C 三件拿得出手的事。」

## 版本 C · 详述版（2.5–3 分钟 / ~700 字）

> 适用：交叉面 / 二面 / 架构面，面试官给你 3 分钟做介绍。关键是**讲故事（背景→挑战→方案→量化结果）**，而不是罗列项目名。

**模板（按 STAR 叙事）**：
> 你好，我叫陈雨寒，6 年全栈与跨端开发，20 届软件工程本科毕业。整体履历是：**四年网易云音乐直播 → 两年半抖音直播，业务一直围绕直播这个大方向**，经历从客户端到工程化再到 AI Agent 的演进。
>
> 目前在抖音直播，我深度参与了两个高难度项目。第一个是**直播鸿蒙端 0-1 建设**——当时鸿蒙业务上要快速拉齐安卓 iOS 能力，但从零写纯 ArkUI 成本高、人跟不上。我作为核心成员推动落地了 H5/Lynx 混合架构，成熟业务用 Lynx，强交互特色能力（LiveView 实况窗、直播卡片、小窗）走原生 ArkTS。同时我主导了 KMP 跨端方案来解三端逻辑重复的问题，把公共业务逻辑沉淀到 Kotlin 共享层，三端共享之后**代码复用率 70%+**，跨语言通信做了批量传输和异步绑定优化，**传输效率再提升 30% 以上**，总体业务迁移成本降低了一半。这个过程让我对"跨端技术选型和收益边界"有很实的体感。
>
> 第二个是**AI Agent Workflow 平台和直播 RAG 知识库**——我们做面向研发场景的智能体平台，我主要负责**全链路诊断与问题排查**这块：给 ReAct 执行引擎加了 traceId / spanId / agentRunId 三级串联，把模型推理、工具调用、沙箱状态变更全部吐 span，形成 Runtime Trace 和 Workflow 阶段账本两个确定性证据，出问题时可以精准定位到哪个 Tool、哪个阶段、哪个沙箱配置出了错。另外我们在 Sandbox 配置同步上用 SHA-256 校验 + 原子替换 + 回滚，解决了多轮会话配置残留导致 TOML 损坏的经典问题——这个坑我觉得做 Agent Runtime 的人基本都踩过。然后和业务知识库一起，把知识库检索封装成 MCP Skill，双路召回 + Query Rewrite + 同义词词典，让 Agent 回答业务问题时事实受知识库约束、幻觉减少。
>
> 网易时期我做两件事：一是**工程化治理**，主导赤兔元框架从单 RN 改造到 RN/Web 双端，做 RN 拆包 + Webpack5 缓存并行，**构建效率 +40%**；二是海豚组件平台一期，做 RN→Web 兼容层与 token 模块化，降低跨平台组件的维护成本 25% 以上。
>
> 所以总结下来，我的优势是：**有跨端（鸿蒙/KMP/RN）和 AI 应用（Agent 可观测/RAG）两条线的复合经验，同时工程化底子扎实**，不是只做业务 UI 的类型。如果岗位里有跨端、AI 平台或者工程化相关的事情，我上手会比较快。很高兴今天有机会交流。

## ★ 自我介绍后的「主动引导」（把节奏握在自己手里）

自我介绍的最后一句，**不要只说"谢谢"**，给面试官一个钩子，让他顺着你最准备充分的点去问。可以三选一：

1. 突出亮点型（引问跨端/鸿蒙/KMP）：
   > 「……其中我在**鸿蒙端 0-1 建设和 KMP 跨端选型**这两块踩坑最多、沉淀最系统，如果您感兴趣我可以再展开讲。」

2. 匹配岗位型（引问 AI/Agent）：
   > 「……我最近两年在 Workflow Agent 的**全链路诊断和评测治理**这块投入比较多，也做了 RAG 双路召回的效果优化，这也是我接下来想继续深耕的方向。」

3. 广度全面型（给面试官自由）：
   > 「……跨端、AI Agent、工程化这三块我都有比较实的落地经验，您这边可以从任何方向深入问我。」

## ★ 容易翻车的 5 个细节（自检）

1. ❌ 不要说「我做了很多模块」——**说 2-3 个带数字的成果**（复用率 70%+ / 性能 30%+ / 构建 40%+），数字一报，可信度立刻上升。
2. ❌ 不要平均分配时间给所有项目——**60% 时间讲最近的抖音（尤其是 0-1 鸿蒙 + Workflow Agent + KMP，这三个最有竞争力）**，40% 讲网易工程化。
3. ❌ 不要用太技术化的词对 HR 面说——HR 版只说「跨平台共享、可观测、构建效率」这类结果词汇，不说 ReAct、MCP、RAG、span。
4. ✅ 所有数字要和简历一致：代码复用率 70%+、通信效率 30%+、构建 +40%、迁移成本 -50%。简历写了什么就说什么，面试不能报新数字。
5. ✅ 结尾一定要引导。面试官不知道你哪块最强，如果不问你准备充分的项目，就会去问你没准备的。引导一次，大概率面试主线就顺了。
