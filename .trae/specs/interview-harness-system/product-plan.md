# Interview Agent Harness 一体化产品方案

> 版本：v1.0 ｜ 定位：一套以"评估—反馈—训练—再评估"闭环为核心的 Agent harness 体系
> 不是五个功能的拼凑，而是**一个共享学习状态机**驱动的多角色 Agent 系统。

***

## 一、为什么是 Harness，而不是功能集合

### 1.1 重新理解需求

用户真正要的不是"一个能面试、能刷题、能做计划的工具"，而是：

> **一个陪我走完求职备考全过程的 AI 训练伙伴——它知道我面过什么、错在哪里、计划做到哪、明天该干什么，并像一个真实的教练团队一样分工协作。**

"harness"（挽具/线束）的含义：把多个 Agent、数据、工具、评估器、调度器**捆在同一条回路上**，让每一次用户行为都产生结构化信号，每一个信号都能驱动下一个动作。

### 1.2 核心闭环（系统的灵魂）

```
        ┌──────────────────────────────────────────────────────┐
        │                                                        │
        ▼                                                        │
  ① 面试演练（面试官 Agent / 面试者 Agent）                         │
     语音/文字多轮对抗                                              │
     │                                                          │
     ▼                                                          │
  ② 结构化评估（评审 Agent）                                       │
     7 维评分 + 强弱标签 + 逐题讲评 + 改进建议                        │
     │                                                          │
     ▼                                                          │
  ③ 诊断归因（教练 Agent）                                         │
     弱项聚类 → 知识点图谱 → 能力雷达                               │
     │                                                          │
     ├──────→ ④ 个性化计划（规划 Agent）                           │
     │          日任务/错题/模拟面/知识卡，带 reason 与 link         │
     │          │                                                │
     │          ▼                                                │
     │       ⑤ 今日执行（驾驶舱）                                  │
     │          打卡 / 勾选 / 计时 / 跳转到对应任务                  │
     │          │                                                │
     │          ▼                                                │
     │       ⑥ 训练（刷题 Agent + 素材库）                          │
     │          作答判分 → 错题本 → 掌握度 → 攻克                   │
     │          │                                                │
     └──────────┴──── 信号全部回写为"能力状态" ────────────────────┘
                                                               │
        ⑦ 激励与触达：streak / 成就 / 提醒通知 ←──── 状态变化驱动 ──┘
```

**关键设计：所有模块共享同一份"用户能力状态"（capability state）。**
面试报告、刷题作答、打卡、任务完成、错题攻克，都是对这份状态的写入；驾驶舱、计划生成、下一次面试难度自适应，都是对这份状态的读取。这是 harness 与"五个独立页面"的本质区别。

### 1.3 与现状的差距（前几版"太简单"的根因）

| 问题            | 根因            | 本方案的解法                                  |
| ------------- | ------------- | --------------------------------------- |
| 页面之间互不相通      | 数据孤岛，各查各的接口   | 统一 `capability state` + 事件回写            |
| 计划是静态清单       | 生成后不再响应用户表现   | 计划每日根据完成度/新报告/错题**动态重排**                |
| 面试只是聊天        | 无结构、无评分、无沉淀   | 面试即评估：每次 session 强制产出结构化报告              |
| 刷题与面试脱节       | 题目标签与弱项不挂钩    | 弱项 tag 双向贯穿：报告 weak\_tags → 题目标签 → 推荐练习 |
| 打卡无反馈         | 打卡只是记录        | 打卡触发 streak/成就/教练评语/明日任务调整              |
| Agent 没有"角色感" | 一个 prompt 走天下 | 多 Agent 分工：面试官/面试者/评审/教练/规划             |

## 二、产品结构：五区一栈

### 2.1 信息架构（五区导航）

```
侧边栏
├── 🏠 今日（home）        —— 驾驶舱：今天干什么、干得怎么样
├── 🎤 面试（interview）
│   ├── 会话（chat）       —— 双角色多轮模拟
│   ├── 报告（reports）    —— 评估历史、趋势、回看、加入计划
│   └── 面设（setup）      —— 岗位/风格/简历
├── ✍️ 训练（practice）     —— 题卡作答 + AI 讲评 + 错题本
├── 📅 复习（review）
│   ├── 复习站（site）     —— 计划日历/任务/素材/打卡日历
│   └── 生成器（planner）  —— AI 生成个性化计划
└── 👤 我的（me）
    ├── 数据（ops/admin）
    ├── 账号（account）
    └── 设置（settings）   —— 主题/通知提醒
```

设计原则：

* **今日是唯一默认落地页**——用户每天打开只需要回答一个问题："今天干什么？"

* 任何一个任务卡片都能**一键跳转到执行场景**（面试/刷题/素材），执行完一键回来，状态自动更新。

* 导航按"使用频率"而非"功能归属"排序。

### 2.2 五大角色 Agent（harness 的执行体）

| Agent                      | 职责                            | 输入                 | 输出                     | 工具                   |
| -------------------------- | ----------------------------- | ------------------ | ---------------------- | -------------------- |
| **面试官 Agent**（interviewer） | 多轮追问、压力面、按岗位出题                | 岗位 JD、简历、历史弱项、当前模式 | 提问、追问、点评               | 读简历、读弱项、计时、写 session |
| **面试者 Agent**（candidate）   | 陪用户反向练习：用户当面试官，AI 作答并制造"典型错误" | 用户出的题、难度           | 回答（可带瑕疵）               | 题库、知识卡               |
| **评审 Agent**（reviewer）     | 面试结束后强制结构化评估                  | session 全文         | 7 维分数/标签/逐题/建议         | 评分 rubric、弱项聚类       |
| **规划 Agent**（planner）      | 生成与动态调整计划                     | 目标、历史报告、错题、可投入时长   | 日任务 DAG（带 reason/link） | 题库检索、任务 CRUD         |
| **教练 Agent**（coach）        | 驾驶舱的"今日建议"与打卡反馈               | 能力状态、今日完成情况        | 一句话建议 + 动作路由           | 读全量状态                |

> 当前实现中，这些角色通过 session.mode + LLM prompt + 后端任务流水线体现；本方案的深化点是让它们**共享工具层与记忆层**（见第四章）。

## 三、分模块产品设计

### 3.1 今日驾驶舱（Home）

**目标**：3 秒内回答"今天该做什么"。

页面自上而下：

1. **Streak 区**：连续打卡火焰 + 今日打卡按钮。未打卡时按钮主色高亮；打卡后展开"学习了多久（分钟）+ 一句话备注"录入。打卡即触发教练 Agent 生成一句当日评语。
2. **AI 教练建议卡**：来自 `/study/dashboard` 的 advice（LLM 优先、规则兜底）。每条建议都是一个**动作**（按钮直接路由）：

   * "你上次模拟面在'系统设计'维度只有 62 分，今天建议做 1 场模拟面" → 一键开面（带 `plan_task_id` + 预设 focus）

   * "错题本有 8 道网络题未攻克" → 跳训练并自动筛选

   * "计划落后 2 天，建议把周末任务前移" → 跳复习站
3. **今日任务卡**（计划当日任务）：

   * 普通任务：勾选完成、记录用时、掌握度。

   * `link_type=interview`：按钮"开始模拟面"→ 直接创建 session（携带 mode/focus/simulation/plan\_task\_id），面试完成后任务自动回写。

   * `link_type=practice`：按钮"去刷题"→ 训练页并按 category 预筛选。

   * `link_type=knowledge`：按钮"去复习"→ 复习站素材定位。

   * 关键任务（critical）红色角标。
4. **四个快捷入口**：开面（面试官/面试者）、刷题、生成计划、复习站。
5. **数据卡**：今日/本周时长、报告数、刷题数、计划完成率。
6. **薄弱项 chips**：点击直达对应题组。

空状态（无计划/未登录）引导：未登录 → 登录卡；已登录无计划 → "AI 生成我的第一份计划"大按钮。

### 3.2 面试模块（Interview）

**双角色对抗**：

* **面试官模式**：AI 提问。支持模式：技术面/行为面（STAR）/压力面/模拟实战（计时、固定题量、不可重开）。

* **面试者模式**：用户当面试官，AI 扮演候选人；可设置"候选人水平"（强/中/弱），弱候选人会埋入典型错误供用户识别——这是"学会面试"的反向训练。

**结构化评估（每次 session 必产出）**：

* 7 维度：技术深度、问题分析、表达逻辑、工程实践、系统设计、沟通协作、岗位匹配（按模式裁剪权重）。

* 逐题得分 + 强弱标签（tags 与题库/知识点共用词表）。

* 改进建议 ≥3 条，每条建议可一键"加入复习计划"（plan picker → `report-tasks` 接口生成任务）。

* 趋势：近 N 次均分、最近均分、雷达对比（报告详情 modal）。

* 报告可"回看会话"→ 还原现场。

**面设（setup）**：目标岗位/职级/公司、风格（温和/压力）、上传简历（AI 出题依据）、模拟时长。

**深化点（harness 化）**：

* 面试官出题时**注入历史弱项**（"上次 Redis 持久化没答清，这次先问它"）。

* 模拟实战模式结束**强制**走评审流水线，评分写回能力状态。

* 计划任务跳来的面试，结束后自动勾选任务 + 把报告新弱项回流计划。

### 3.3 训练模块（Practice）

* **题卡作答**：选择题点选即提交（即时判分）；主观题文字作答 → AI 按要点打分讲评（feedback + 参考答案 + suggestions）。

* **计时器**：单题用时自动采集（elapsed\_seconds），用于"超时题"分析。

* **错题本闭环**：答错自动收录；重做正确/手动"标记掌握"移除；掌握度 5 星；统计待清/已攻克。

* **筛选与随机**：分类/难度/题型/关键词全部真实传参；"随机一组"从总量中真随机抽题（不是写死 10 题）。

* **统计卡**：累计作答、正确率、本周/今日、错题存量（来自 dashboard 聚合）。

**深化点**：

* 错题的 tags 与报告 weak\_tags 共用词表 → 训练页"为你推荐"题组 = 最新报告弱项 ∪ 高频错题标签。

* 连续 2 次答对且用时低于阈值 → 自动升掌握度；引入间隔重复（1/3/7 天后重现错题）。

### 3.4 复习模块（Review）

**复习站（review-site）**：

* 日历视图：打卡日高亮、连续 streak、今日计划进度条。

* 计划日/任务 CRUD：天级增删改、任务级增删改、拖拽排序（sort\_order）。

* 素材库三类：

  * **自我介绍话术**（intro\_scripts）：版本管理 + 练习次数持久化。

  * **STAR 明星案例卡**（star\_cards）：情境/任务/行动/结果四段式。

  * **A4 记忆纸**（a4\_memory）：一页纸速记知识点。

* 今日 Tab：真实 `/today` 数据 + 打卡按钮 + 分钟数录入。

* 成就墙：GET /study/achievements，解锁 toast + 徽章（streak 7 天、首份报告、错题清零等）。

**生成器（planner）**：

* 表单：标题、目标岗位、职级、目标公司、总天数（3–90）、每日时长、侧重领域、模板、关联简历。

* **use\_history 开关（默认开）**：把历史报告弱项 + 错题分布喂给规划 Agent，生成的计划任务带 `reason`（为什么有这条任务）与 `link`（做完跳哪）。

* generated\_by 标识（llm/rule）透明展示；LLM 不可用时规则模板兜底。

* 生成后可在复习站继续手工微调（CRUD 已通）。

**深化点（动态计划）**：

* 每日打卡时教练 Agent 检查：任务完成率 <60% → 建议压缩/顺延；出现新弱项报告 → 未来 3 天插入对应任务；错题攻克 → 减少重复任务。规划 Agent 的"重排"是下阶段核心增量。

### 3.5 我的（Me）

* 账号：资料、目标岗位。

* 设置：主题（浅/深，token 体系双主题）、**每日提醒**（开关 + 时间 + 立即测试；Electron 本地通知，点击唤出窗口；无活跃计划时置灰提示）。

* 管理（admin）：数据运维。

## 四、Agent Harness 技术架构

### 4.1 分层

```
┌─────────────────────────────────────────────────┐
│  交互层  Electron + React（五区 IA / SSE 流式）     │
├─────────────────────────────────────────────────┤
│  Agent 编排层                                    │
│   ├─ Interviewer/Candidate Agent（多轮对话+模式）   │
│   ├─ Reviewer Agent（结构化评分流水线）             │
│   ├─ Planner Agent（LLM 生成 + 规则兜底）          │
│   └─ Coach Agent（建议/评语，LLM+规则）            │
├─────────────────────────────────────────────────┤
│  能力状态层（harness 核心）                         │
│   ├─ capability state：tag→掌握度/出现频次/来源      │
│   ├─ 事件流：report / attempt / checkin / taskdone │
│   └─ 记忆：简历、目标、历史会话摘要                  │
├─────────────────────────────────────────────────┤
│  工具层  题库检索 / 计划 CRUD / 打卡 / 通知 / 计时   │
├─────────────────────────────────────────────────┤
│  数据层  PostgreSQL（会话/报告/作答/错题/计划/打卡/成就）│
└─────────────────────────────────────────────────┘
```

### 4.2 能力状态（Capability State）

系统维护一张随事件更新的"知识—能力"聚合：

* **来源事件**：面试报告（dimension\_scores、weakness\_tags、per\_question）、刷题作答（correct、用时、tags）、错题标记（mastery\_level）、任务完成。

* **形态**：`tag → {score, mastery, frequency, last_seen, sources[]}`，外加 7 维能力分的时间序列。

* **消费者**：面试官出题（注入弱项）、规划 Agent（排任务权重）、教练建议（advice）、训练推荐（题组排序）。

* 当前已部分实现：dashboard 的 weak\_points/advice、报告 tags、错题 tags。深化点是**统一词表 + 掌握度衰减模型 + 间隔重复调度**。

### 4.3 评估即流水线（Evaluation Pipeline）

面试 session 完成 → 后台流水线：

1. 全文结构化（逐题切分）。
2. Reviewer Agent 按 rubric 打分（JSON schema 强约束，失败重试 + 规则兜底）。
3. 弱项标签聚类 → 写 capability state。
4. 触发成就检查、趋势更新。
5. 若 session 关联 plan\_task → 回写任务完成、生成"加入计划"候选建议。

原则：**所有 Agent 输出都必须落结构化数据**，自由文本只是给用户看的视图。这保证 harness 永远可计算、可重放、可回归。

### 4.4 计划即 DAG

计划不是清单，是带依赖与链接的任务图：

* 节点：任务（面试/刷题/知识/复盘），边：先后顺序与 sort\_order。

* 每个节点有 `reason`（可解释）和 `link_type/link_payload`（可执行）。

* 规划 Agent 生成后允许用户手工改（CRUD），用户修改与 Agent 重排通过 reason 共存。

### 4.5 触达系统

* **打卡/streak**：每日 checkin（分钟+备注）→ 连续天数、日历热力。

* **成就引擎**：规则化徽章（首面、7 天 streak、错题清零、满分报告…），解锁即 toast。

* **本地通知**：Electron 主进程定时（无需后端在线），点击唤出到今日页；提醒内容由"今日未完成任务 + streak 将断"动态生成。

## 五、交互与视觉体系

### 5.1 交互原则

1. **一屏一问题**：今日页只回答"今天干什么"；训练页只回答"这题怎么答"。
2. **任何任务 ≤2 次点击可达执行**：卡片 → 场景 → 完成自动回写。
3. **状态可见**：进度条、streak、掌握度星、分数色阶（≥85 绿 / ≥70 琥珀 / 否则红）。
4. **AI 永远给动作**：建议不是文字，是带按钮的路由。
5. **空状态即引导**：未登录→登录；无计划→生成；无报告→开第一场面；错题空→鼓励。
6. **错误轻提示**：alert/inline hint，不阻断流程；加载用骨架/旋转。

### 5.2 视觉规范（去 AI 味）

* 扁平、低饱和、大留白；圆角 12px 卡片 / 8px 控件。

* 纯 lucide 线性图标，禁 emoji 当功能图标。

* 全部颜色走 CSS token（`--panel/--line/--text/--muted/--blue/--green/--amber/--red` 及 \*-soft），浅/深双主题由 token 块切换，禁止硬编码色。

* 字号层级：页标题 20 / 卡片标题 15–16 / 正文 14 / 辅助 12。

* 按钮三级：primary（蓝实心）/ ghost（描边）/ icon（30px 方形）。

## 六、数据与接口现状（已落地）

* 面试：sessions（mode/plan\_task\_id）、`GET /interview-reports`、`GET /interview-reports/{id}`、报告回流 `POST report-tasks`。

* 学习：`GET /study/dashboard`（streak/今日任务/时长/面试/刷题/计划/弱项/advice）、`GET /study/achievements`。

* 复习：plans/days/tasks/materials 全 CRUD、`/today`、`/checkin`、`/checkins`、progress PATCH、planner/generate（use\_history）。

* 刷题：questions 列表、`/attempt`（AI 判分）、`/attempts`、`/mark`、wrong-book。

* 端侧：Electron 通知 IPC（test/schedule/cancel，重启恢复）、统一 `api:request` 通道（复用鉴权与 SSE）。

## 七、迭代路线

**P0（闭环跑通，当前阶段收尾）**

* 五区 IA、今日驾驶舱、报告中心、训练页（已建）✅

* 复习站今日 Tab 真实数据 + 打卡 + 成就墙

* 生成器 use\_history / 简历关联 / reason 展示

* 素材库三类 CRUD + 提醒设置

* 双主题走查 + 构建/测试回归

**P1（harness 深化）**

* 统一能力状态服务：tag 词表 + 掌握度衰减 + 时间序列

* 计划动态重排：打卡后教练 Agent 每日微调任务

* 面试官出题注入弱项；模拟实战强制评估

* 间隔重复：错题 1/3/7 天重现；超时题标记

* 报告雷达对比（多场叠加）

**P2（体验与智能）**

* 语音面试（ASR/TTS）与语气评分

* 面试者模式"候选人水平"分级与错误埋点

* 周/月报：自动生成一周复盘 + 下周计划

* 计划模板市场（校招/社招/转行/考公）

* 数据导出与离线缓存增强

## 八、成功指标

| 维度   | 指标                           |
| ---- | ---------------------------- |
| 闭环激活 | 首场模拟面 → 生成报告 → 加入计划 的转化率     |
| 留存   | streak 7 日留存、日活打卡率           |
| 训练效果 | 报告均分趋势（近 5 场 vs 前 5 场）、错题攻克率 |
| 计划执行 | 计划任务当日完成率、计划 7 日存活           |
| 体验   | 核心路径点击深度（≤2）、崩溃/构建错误为 0      |
