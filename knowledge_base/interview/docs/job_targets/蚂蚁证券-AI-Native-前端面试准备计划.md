# 蚂蚁集团证券 AI Native 大前端岗位准备

## 1. 岗位一句话判断

这个岗位不是单纯招前端页面开发，也不是单纯招客户端开发。它更像是：

> 证券业务场景下的大前端架构工程师，既要能做移动端 H5 / Hybrid / 容器 / 跨端，也要能做性能稳定性治理，还要能把 AI Coding、Agent、Context、Knowledge、Skill 这些能力接入研发流程。

你的经历和这个岗位的匹配点比较强，核心不是“我会 RN / Lynx / KMP”，而是要讲成：

> 我过去做的是直播复杂业务里的大前端基础设施：端侧复杂链路、Hybrid 容器、KMP 跨端、性能治理、AI Agent 工程化。这些能力迁移到证券场景，就是行情高频渲染、交易链路稳定性、财富 H5 容器、投研/机构服务的 AI Native 研发平台。

### 3.3 主线三：高频数据渲染和性能治理

岗位关键词：

- 行情市场扩展。
- 高频数据渲染。
- 启动、功耗、卡顿、内存、网络。
- 绘图、动画、协议、安全、性能。

你的对应经历：

- 直播高频消息。
- 短触队列。
- 第三行活动入口。
- 小窗 / 画中画。
- 直播回放容器。
- Lynx 长列表。
- RN 长列表。
- KMP 消息解析和 rawPayload。

证券场景映射：

| 直播场景 | 证券场景 | 共性问题 |
|---|---|---|
| 公屏 / 礼物 / 短触消息 | 行情 tick / 盘口 / 分时 / 成交明细 | 高频数据输入，不能每条都刷新全 UI |
| 播放器首帧 / 卡顿 | 行情首屏 / K 线加载 | 首屏速度、资源预加载、异步链路 |
| 小窗 / PiP | 行情后台关注 / 自选股提醒 | 生命周期、功耗、资源降级 |
| Lynx 活动卡片 | 财富活动 / 投顾服务卡片 | 容器首屏、JSB、安全、降级 |
| KMP 消息解析 | 行情协议解析 / 字段口径统一 | 多端模型、协议、默认值一致 |

高频渲染回答框架：

```text
数据入口
  -> 端侧过滤
  -> 聚合 / 去重 / 合批
  -> 节流到 UI 可承受频率
  -> 局部状态更新
  -> 列表 / 图表增量渲染
  -> 指标监控和降级
```

你应该准备的细节：

- 行情 tick 不能每条驱动 React / Lynx 全量 setState。
- UI 刷新应该按帧率或业务频率合批。
- 盘口、成交明细、榜单类列表要做窗口化和局部更新。
- K 线 / 分时图更适合 Canvas / Native / Skia / 平台绘图能力。
- 网络层要考虑断线重连、增量同步、快照 + 增量。
- 弱网下要有降级和过期数据标识。

可以这样回答：

> 我过去处理直播实时消息时，核心经验是不能让每条消息直接驱动 UI。需要先在端侧做过滤、聚合、节流，再转成局部状态更新。证券行情也是类似，高频 tick、盘口和成交明细不能全量 setState，而要快照 + 增量、窗口化列表、局部 diff、必要时用 Canvas 或 Native 绘图承接。

## 5. 你的项目怎么重新包装

### 5.1 开播架构

原始表达：

> 我做过直播开播链路。

岗位化表达：

> 我做过复杂端侧业务链路的平台化治理。开播链路涉及页面、状态机、推流、工具栏、组件挂载、生命周期、失败恢复和埋点。我负责把链路拆成核心控制器、生命周期任务、Tetris Element、配置和服务能力，避免业务功能直接耦合主链路。

## 7. 可能被问的重点问题

### Q1：你为什么适合证券业务，而不是只适合直播？

回答重点：

> 直播和证券看起来业务不同，但技术挑战有很多共性。直播有实时消息、复杂生命周期、高频 UI、强稳定性和端前容器；证券有行情 tick、盘口、K 线、交易链路、账户态和风控。两者都要求实时、稳定、低延迟、强上下文一致。我过去处理的是直播复杂场景，迁移到证券时，我会重点补业务知识，但底层工程能力是能复用的。

### Q2：行情高频数据你会怎么做？

回答结构：

```text
数据层
  -> 快照 + 增量
  -> WebSocket / 长连接
  -> sequence / timestamp 校验

计算层
  -> 去重 / 合批 / 节流
  -> 只保留最新状态

渲染层
  -> 局部更新
  -> 长列表窗口化
  -> 图表用 Canvas / Native 绘制

稳定性
  -> 断线重连
  -> 弱网降级
  -> 过期数据标识
  -> 监控首屏和刷新延迟
```

### Q3：Hybrid 容器怎么设计？

回答重点：

> 我会把容器拆成路由解析、资源加载、上下文注入、JSB 注册、生命周期、权限和监控几层。证券场景下要特别注意账户态、交易权限和行情上下文，不能让 H5 直接拿敏感能力，而是通过容器做白名单、参数校验和权限判断。

### Q4：RN、Lynx、KMP 怎么选？

回答重点：

> RN 适合页面级跨端，Lynx 适合动态化活动和卡片，KMP 适合共享业务逻辑和状态机。证券里，财富活动页可以 Lynx/H5，普通双端页面可以 RN，行情模型、交易状态、埋点口径可以 KMP 或共享逻辑层，强平台能力保留原生。

### Q5：AI Native 你准备怎么落地？

回答重点：
